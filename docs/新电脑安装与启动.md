# Windows 新电脑从零安装与启动

2026-11-04。适用范围是 Windows x64、PowerShell、单用户本机运行。旧电脑实际验证 Python 3.13.7；其他系统/版本没有本项目复现验收。本轮未在一台全新电脑重装，不将下列操作说明写成新机实测成功。所有命令由 Coding Agent 执行或协助执行；用户只需私下填写凭证和审核文案。

## 1. 准备工具与目录

从 [Python 官方 Windows 下载页](https://www.python.org/downloads/windows/)安装64位Python，优先复现3.13.7；从 [Git 官方](https://git-scm.com/downloads/win)安装Git。两者安装涉及系统组件，应由机器所有者确认后操作，本轮没有执行安装。使用独立虚拟环境，不向系统Python安装项目包。

从 https://github.com/Komatsu-Nana-CPU/ContentFlow 获取源码，放到任意可写目录，如 D:\Projects\ContentFlow。首次获取可执行 `git clone https://github.com/Komatsu-Nana-CPU/ContentFlow.git D:\Projects\ContentFlow`，已有目录不要覆盖。旁边准备独立 MoneyPrinterTurbo；避免复制旧机器 .venv，必须重建。下面在 PowerShell 设置本次操作变量，目录可换，重新开终端后需重设：

```powershell
$cfDir = 'D:\Projects\ContentFlow'
$mptDir = 'D:\Projects\MoneyPrinterTurbo'
$pyExe = (Get-Command python).Source
& $pyExe --version
git --version
```

检查 `$pyExe` 是真实 Python 3.13.7，而非Windows商店占位程序。安装依赖需要访问GitHub、PyPI及包下载域名；网络失败先定位，不自动换引擎版本或付费服务。预留多GB依赖/缓存空间和素材工作空间；已见单个4K素材约202MiB，不承诺固定磁盘峰值。

## 2. 获取并固定上游

只在目标目录尚不存在时获取，已有目录先检查，不覆盖现有代码/素材/config：

```powershell
git clone https://github.com/harry0703/MoneyPrinterTurbo.git $mptDir
git -C $mptDir checkout --detach 436b0e9cc830ef7639e33388917e389cf30d3307
git -C $mptDir rev-parse HEAD
Get-FileHash -LiteralPath "$mptDir\uv.lock" -Algorithm SHA256
```

必须是 commit `436b0e9cc830ef7639e33388917e389cf30d3307`，项目/API版本1.3.6；uv.lock SHA-256必须为 `497a686501e5f0023e7d671ff0c650d944a75d93ac46a2edb6cc61065cfb5668`。不要按最新版main升级。若完整clone受阻，可获取同SHA的官方归档 `https://github.com/harry0703/MoneyPrinterTurbo/archive/436b0e9cc830ef7639e33388917e389cf30d3307.zip`，检查锁文件和已存源码指纹再继续；归档没有.git，不能声称通过rev-parse。旧电脑实际是53文件API子集，不是完整clone；此处新机完整获取流程尚未实测。

## 3. 两个隔离环境及 Edge 例外

工具uv仅装入上游.bootstrap，不改全局PATH。以下是已批准的独立安装方式，第一次执行前确认路径和权限：

```powershell
& $pyExe -m venv "$mptDir\.bootstrap"
& "$mptDir\.bootstrap\Scripts\python.exe" -m pip install uv==0.13.6
$uvExe = "$mptDir\.bootstrap\Scripts\uv.exe"
& $uvExe sync --frozen --no-dev --python $pyExe --cache-dir "$mptDir\.uv-cache" --project $mptDir
& $uvExe pip install --python "$mptDir\.venv\Scripts\python.exe" --cache-dir "$mptDir\.uv-cache" --no-deps edge-tts==7.3.1
& $uvExe pip check --python "$mptDir\.venv\Scripts\python.exe"
& "$mptDir\.venv\Scripts\python.exe" -c "import importlib.metadata as m; print(m.version('edge-tts'))"
& $pyExe -m venv "$cfDir\.venv"
& $uvExe pip install --python "$cfDir\.venv\Scripts\python.exe" --cache-dir "$mptDir\.uv-cache" -r "$cfDir\requirements.lock.txt"
& $uvExe pip check --python "$cfDir\.venv\Scripts\python.exe"
```

上游原锁为edge-tts7.2.7，曾在配音握手返回403；用户批准仅独立.venv覆盖为7.3.1后真实成功，原源码/pyproject/锁文件均不变。这是明确依赖例外，不能声称环境完全等于原锁。[原例外证据](evidence/round005_dependency_override.json)。以后 `uv sync --frozen` 会恢复7.2.7，必须重做批准的7.3.1覆盖；正常启动直接使用.venv Python，避免 `uv run` 自动同步。[uv同步规则](https://docs.astral.sh/uv/concepts/projects/sync/)。

若需回退，仅在无活动任务时停止后端，再执行：

```powershell
& $uvExe pip install --python "$mptDir\.venv\Scripts\python.exe" --no-deps edge-tts==7.2.7
```

回退不代表旧403已解决。requirements.lock.txt是ContentFlow精确版本清单，不含包哈希；只在原Windows/Python组合验证过，不把锁清单等同于跨平台保证。

## 4. 字体、FFmpeg与本机路径

Windows已有授权中文字体通常位于 `$env:WINDIR\Fonts\msyhbd.ttc`。不要把Windows字体复制到GitHub。不同机器缺失时安装有许可的中文字体，并把实际字体路径交给Agent配置；不能假定英文默认字体能显示中文。

优先用MPT独立环境的imageio-ffmpeg二进制，不需要全局FFmpeg或修改PATH：

```powershell
& "$mptDir\.venv\Scripts\python.exe" -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
```

把返回路径的可执行文件运行 `-version` 检查；旧电脑实际FFmpeg7.1。下载受阻、文件不存在或系统限制执行时停止，向用户说明具体修复，不静默安装系统组件。

在ContentFlow目录执行AI提供的配置工具。首次没有上游config.toml时可加 `--init-mpt-config`：

```powershell
Set-Location $cfDir
& .\.venv\Scripts\python.exe -B scripts/configure_local.py --mpt-dir $mptDir --font-path "$env:WINDIR\Fonts\msyhbd.ttc" --init-mpt-config
```

该选项新建最小安全配置：只监听127.0.0.1:8080、Flash、Edge字幕、无Redis、关闭自动发布、一个并发任务；密钥留空。若config已存在，工具停止而不覆盖；去掉 `--init-mpt-config` 只保存ContentFlow机器路径。不会把上游私有配置复制到项目中。

如上游需要显式FFmpeg路径，在首次配置命令加 `--ffmpeg-path '实际的ffmpeg.exe完整路径'`，初始化时同步写入上游app.ffmpeg_path；已有上游配置不被改写，应由Agent核对并更新私有字段，ContentFlow侧同样用该路径解码验证。字体路径必须在MPT服务机器实际存在，本项目仅支持两服务同机。

工具创建被忽略的config.local.json，字段mpt_dir、mpt_url、font_path、ffmpeg_path。路径优先级：显式函数参数（仅内部MPT目录）→环境变量→本机JSON→同级MoneyPrinterTurbo/Windows字体默认；FFmpeg未显式设置时复用上游app.ffmpeg_path或其imageio捆绑二进制。相对路径按进程工作目录解析，建议传绝对路径。

可选环境变量：CONTENTFLOW_MPT_DIR、CONTENTFLOW_FONT_PATH、CONTENTFLOW_FFMPEG_PATH；CONTENTFLOW_ROOT可指定另一数据根目录（通常不设置）。变量在新终端会丢失；不通过全局PATH解决项目路径。地址由config.local.json的mpt_url设置，仅允许本机HTTP；改端口时需同时核对上游listen_port。

## 5. 私下配置已有凭证

MoneyPrinterTurbo目录的config.toml：`[app].pixabay_api_keys`为数组；已有`deepseek_api_key`、`deepseek_model_name="deepseek-flash"`、`llm_provider="deepseek"`、`subtitle_provider="edge"`。用户可在后面启动的ContentFlow侧栏密码框填写两个已有Key，空输入保留旧值，不在聊天发送。

素材Key保存后先确认无活动任务，再在后端终端Ctrl+C停止并重新运行main.py。DeepSeek由ContentFlow每次请求前加载；不会默认读取.env。可用DEEPSEEK_API_KEY环境变量覆盖，但不建议再建一份重复凭证。可选上游app.api_key与MPT_API_KEY为本机REST鉴权，与DeepSeek/Pixabay凭证不同；检查工具不接收命令行明文密钥，启用鉴权后用网页“检查视频服务”。

不要配置自动发布、Pro、付费视频服务或Whisper下载回退；DeepSeek现有余额会计费，未审核不能创建视频。本轮没有重装依赖或调用计费服务。

## 6. 两个终端启动与只读检查

后端终端（实际路径可替换）：

```powershell
Set-Location D:\Projects\MoneyPrinterTurbo
& .\.venv\Scripts\python.exe main.py
```

前端另开终端：

```powershell
Set-Location D:\Projects\ContentFlow
& .\.venv\Scripts\python.exe -m streamlit run app.py
```

打开 `http://127.0.0.1:8501`，后端OpenAPI为 `http://127.0.0.1:8080/docs`；两进程需保持运行，不是自启动服务。未启用MPT鉴权时可只读检查：

```powershell
& .\.venv\Scripts\python.exe -B scripts/check_mpt_api.py --base-url http://127.0.0.1:8080
& .\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
$env:CONTENTFLOW_MPT_DIR = 'D:\Projects\MoneyPrinterTurbo'
& "$env:CONTENTFLOW_MPT_DIR\.venv\Scripts\python.exe" -B scripts/test_mpt_material_contract.py
```

最后一项模拟HTTP，不调用素材/模型/生成。首次真实联调先侧栏独立素材检索，再生成草稿并人工审核；这会使用现有模型余额，须与本轮纯整改区分。Edge免费联网路径也可能403或超时，不能保证长期可用。

## 7. 数据、停止与恢复

ContentFlow数据为runtime/contentflow下SQLite和videos，MPT数据在其storage下。公开仓库不带旧样片/数据库/日志；新电脑从空历史开始，不应出现旧任务。迁移历史前由Agent备份，停止两服务后复制受管数据并核对路径/哈希；不覆盖旧样片，不把备份提交Git。

下载保存失败显示“下载失败”：修复目录权限、磁盘空间或文件占用后点“重试下载”，沿用原task_id，仅GET，不会重新生成。后端重启丢失任务时进入“需核对”，保留storage中的成片与原ID，先核实再处理，不能靠新建任务解决未知结果。没有端到端断点续传保证。
