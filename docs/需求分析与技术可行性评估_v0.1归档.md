# ContentFlow 需求分析与技术可行性评估

版本：v0.1（需求讨论稿，未冻结）  
日期：2026-10-31（Asia/Shanghai）  
阶段：需求分析；本阶段不编写程序代码、不安装依赖、不启动外部服务。

## 1. 结论与项目定位

建议建设一个面向课程演示的单用户 AI 内容工作流系统：用户输入创作方向，由 AI 提出选题和脚本，用户审核后，系统组织素材并调用已有视频工具生成短视频，全程可查看状态、产物和失败原因。

**技术判断：有条件可行。** 已有开源工具具备视频生产能力，主要工程工作在于流程编排、人工审核、状态持久化、工具适配和可追溯性。当前只完成目录检查及公开资料核验，尚未完成本机部署、接口联调、性能或成本实测，因此不能宣称已打通视频生成。

课程价值应体现在：从需求到验收的工程闭环，以及对 AI 工作流的可靠管理。直接替换 MoneyPrinterTurbo 的页面或增加聊天入口，不足以体现本项目的主要贡献。

## 3. 背景、利益相关者与目标

目标用户是需要演示自动化内容生产过程的学生或单人创作者。课程教师关注需求完整性、设计合理性、实现质量、测试证据和 AI 辅助开发记录。开发者通过自然语言提出需求、审核 AI 产物、运行验证并解释设计，不手工编写或修补程序代码。

业务问题：选题、脚本、素材和视频工具彼此割裂；长时间任务缺乏状态；失败后难以判断原因；生成结果难以追溯到输入和配置。

项目目标：

1. 从创作方向形成一个可审核、可执行的视频任务。
2. 至少完成一个真实的“选题—脚本—素材—视频”闭环。
3. 记录每一步的输入摘要、产物、状态、时间和错误，能够关联到同一任务。
4. 将开发过程按自然语言交互轮次归档，真实保留失败和修改依据。

## 4. 边界与前提

本稿暂按“一个本地工作站、一个使用者、中文界面、一个 LLM 服务、一个视频后端”设计。提交期限、团队人数、API 预算、硬件配置、教师指定技术栈尚待用户补充。

“自动化”指已审核输入之后自动执行步骤；MVP 保留脚本和素材审核，不承诺无人值守发布。选题是根据用户方向提出创意，不代表实时热榜、搜索事实核验或市场预测。

“AI Agent”在本项目中的可验收定义：模型基于目标输出结构化选题、脚本和素材检索词，系统校验后调用白名单工具，并根据执行结果进入下一状态或失败处理。执行顺序由固定工作流控制，不允许模型执行任意命令。本稿不要求多个自主 Agent 或自由规划框架。

## 5. MVP 范围

### 5.1 必须交付（P0）

| 模块 | 最小范围 |
| --- | --- |
| 任务管理 | 创建、列表、详情；本地持久保存任务和历史 |
| 选题辅助 | 根据方向生成 3 个候选选题，允许选择一个或直接指定主题 |
| 脚本辅助 | 生成中文口播稿与素材关键词；支持自然语言修改及人工确认 |
| 素材处理 | 上传并校验本地 MP4 素材，查看清单、来源说明并确认使用 |
| 视频生成 | 复用 MoneyPrinterTurbo 生成配音、字幕及合成视频；单次产出一个 MP4 |
| 工作流管理 | 显示实际阶段、运行状态、错误、有限重试；同时最多一个生成任务 |
| 结果交付 | 浏览器预览和下载成片，查看已确认脚本、素材清单及运行记录 |
| 配置 | 本地配置 LLM、TTS、视频服务连接信息；日志隐藏密钥 |
| 工程记录 | 需求、设计、交互记录、验证结果及开源贡献边界可追溯 |

默认视频模板为竖屏 9:16、720×1280、中文、单配音、烧录字幕；成片目标时长 30–60 秒，以语音实际长度为准。超出范围提示调整脚本，不直接截断句子。参数支持程度需在适配验证后确认。

背景音乐默认关闭；若开启，仅使用用户提供且说明使用权限的音频。无本地素材时明确阻止合成，不用空白画面伪装成功。

### 5.2 可选增强（P1，P0 验收后再考虑）

- 接入一个在线素材源，例如 Pexels；下载后仍需展示来源和确认。
- 增加横屏、1080p 或少量字幕样式。
- 导出一份任务报告，展示耗时、失败与产物清单。

### 5.3 不进入本次 MVP（P2）

多用户权限、商业计费、云集群、高并发、拖拽式通用 DAG 编辑器、多 Agent 自主协商、实时热点爬虫、自动发布到社交平台、训练大模型、文生视频模型、数字人、专业时间线剪辑器和自动版权判定。

本地素材是 P0 的正式输入方式，不是伪造在线检索的替代品；在线检索属于可选范围。使用云 LLM/TTS 时仍依赖网络，本地素材模式不等于完全离线。

## 6. 用户场景与交互流程

### UC-01：创建并完成一个任务

前置条件：服务配置通过检查，至少有一组可用素材。

1. 用户输入方向、受众、风格和时长目标，例如“向大学生介绍番茄工作法，轻松、约 45 秒”。
2. 系统生成三个不同角度的选题及简短理由；用户选择其一。
3. 系统生成脚本、预估时长和素材关键词；用户可输入“更口语化、删去第二点”等修改要求。
4. 用户确认脚本，形成不可覆盖的脚本版本快照。
5. 用户上传本地视频，系统校验并展示素材清单、时长、来源说明；用户确认。
6. 系统提交生成任务，显示本地阶段和上游实际状态。
7. 完成后用户预览、下载 MP4，并能查看脚本版本和执行记录。

后置条件：任务成功且产物可播放，或任务失败并给出明确错误及处理入口。

### UC-02：处理失败

LLM 超时可有限自动重试；密钥无效应直接提示修正配置。素材损坏时拒绝并说明原因。视频后端不可达时保留已确认脚本和素材，修复后允许用户创建新尝试。

提交生成请求超时但不确定上游是否已接收时，标记“需核对”，先查询关联任务，禁止盲目重复提交。用户修订已确认脚本后，素材确认及其下游产物失效，旧成片仍保留在旧尝试中。

以下均为计划验收标准，尚未执行。

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-01 | P0 | 创建内容任务 | 方向不能为空；校验失败不调用外部服务；成功分配唯一任务标识 |

| FR-04 | P0 | 人工审核 | 未确认脚本或素材不可启动生成；修订脚本使旧的下游确认失效 |
| FR-05 | P0 | 本地素材导入 | 接受含视频流且能解码的 MP4；单文件最多 100 MB，每任务最多 10 个；拒绝伪装扩展名和越界路径 |
| FR-06 | P0 | 素材确认 | 展示名称、来源说明和元数据；至少一个有效素材；素材不足以满足模板要求时阻止生成并提示 |

| FR-08 | P0 | 生成及交付 | 获得有中文配音、可见字幕的 9:16 MP4；输出规格和实际时长可查；预览及下载均可用 |
| FR-09 | P0 | 状态与错误 | 展示当前阶段、开始结束时间、错误摘要；无上游精细进度时显示“生成中”，不编造百分比 |
| FR-10 | P0 | 重试控制 | 网络瞬时失败最多自动重试 2 次；参数或鉴权错误不自动重试；新生成尝试有独立编号 |
| FR-11 | P0 | 持久化及恢复 | 重启后已确认输入和历史可查；未完成任务进入核对流程，不直接宣称成功或自动重复提交 |
| FR-12 | P0 | 配置与日志 | 缺失配置有明确提示；页面及导出记录不出现完整密钥；记录模型名称和提示词版本 |
| FR-13 | P0 | 并发限制 | 重复点击不重复创建同一次本地请求；运行中第二个生成请求明确提示等待，不无提示丢失 |
| FR-14 | P1 | 在线素材检索 | 显示来源页、作者及获取时间；空结果和限流可理解；允许改用本地素材 |

## 8. 非功能需求

| 编号 | 要求 | 拟定衡量方法 |
| --- | --- | --- |
| NFR-01 易用性 | 中文引导，表单能解释缺失项与下一步 | 使用说明带领新用户完成一次完整演示 |
| NFR-02 响应 | 本地提交确认目标 2 秒内，状态刷新间隔不超过 5 秒 | 标明测试机器，记录实际用时；外部生成另计 |
| NFR-03 可靠性 | 无无限重试、无静默失败；失败不覆盖成功产物 | 注入超时、鉴权失败、服务停止并检查状态与文件 |
| NFR-04 可追溯性 | 每次尝试均能还原其输入版本和配置摘要 | 从成片追到任务、脚本、素材、模型及上游任务 |
| NFR-05 数据保护 | 默认仅监听本机；密钥留在本地私有配置，上传路径受限 | 检查访问边界、日志脱敏及路径校验 |
| NFR-06 可维护性 | 工作流与上游 API 通过适配层隔离 | 用模拟后端验证状态转换，再以真实后端联调 |
| NFR-07 视频质量 | 可播放、无字幕乱码或明显裁切、配音可辨识 | 人工完整观看；记录分辨率、编码、时长和样例截图 |

性能试验基准建议为 4 核以上 CPU、8 GB 以上内存、至少 10 GB 可用磁盘，云 LLM/TTS、无独立 GPU 前提；这是本项目的待验证预算，不是已测最低配置。单条 30–60 秒视频暂以 10 分钟内完成为实验目标，先测量再冻结，不作为已有承诺。合成阶段建议 15 分钟告警并进入核对，不等同于已取消上游任务。

## 9. 概念数据与状态约束

| 对象 | 需记录的信息 |
| --- | --- |
| 内容任务 | 标识、方向、受众、主题、目标时长、当前阶段、状态、创建时间 |
| 脚本版本 | 正文、关键词、版本、模型与提示词版本、审核时间 |
| 素材 | 本地存储标识、校验摘要、格式、时长、来源页或用户说明、使用权限说明 |
| 执行尝试 | 尝试编号、输入快照、上游任务标识、各阶段状态、错误、重试次数、起止时间 |
| 输出产物 | 所属尝试、文件标识、类型、分辨率、时长、生成时间 |
| 事件 | 关联标识、阶段、操作、时间、脱敏摘要 |

任务主流程：草稿 → 选题生成 → 待选题确认 → 脚本生成 → 待脚本确认 → 待素材确认 → 视频生成 → 成功。自动步骤可转入失败；存在不确定上游执行结果时转入“需核对”。失败重试生成新尝试，保留历史。

审核等待可跨进程重启。恢复中的上游任务先核对状态；上游无记录则提示重新发起。MVP 不承诺进程崩溃后的字节级合成断点续传或任意子步骤恢复。上游 API 若仅提供整体生成状态，本地只展示整体状态，不推断配音、字幕、合成分别已完成。

## 10. 技术可行性与建议架构

### 10.1 已核验的上游能力

截至本轮查询，上游 README 描述了脚本、素材、字幕及视频合成流程，并提供 WebUI/API 入口；Python 版本要求为 3.11+。这些信息支持复用视频后端的方向，但不构成本机可运行证明。[上游 README](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/README.md)

当前主分支视频控制器存在生成、任务查询、本地素材上传及产物访问接口。这支持“提交任务—轮询—取回产物”的适配思路；具体路由前缀、请求字段、鉴权、素材映射和状态含义必须基于后续锁定版本验证，不应把主分支接口视为稳定协议。[上游视频控制器](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/controllers/v1/video.py)

在线素材若选择 Pexels，需要 API key，并遵循 API 归属展示要求和限流规则；因此不是无条件可用的依赖。MVP 将它放到可选增强。[Pexels API 文档](https://www.pexels.com/api/documentation/)

### 10.2 架构建议（待下一阶段确认）

浏览器界面 → ContentFlow 应用层 → 固定工作流与持久化 → LLM 适配器 / 视频适配器 → 外部模型服务 / 本地 MoneyPrinterTurbo。元数据保存到 SQLite，素材和产物保存到独立本地目录。

| 组件 | 建议 | 理由及代价 |
| --- | --- | --- |
| 界面 | Streamlit | 单人课程项目页面少，可降低前端工作量；复杂交互扩展能力有限 |
| 业务与编排 | Python 3.11，显式状态机 | 便于复用 Python 生态，流程可测；状态与重试需自行明确设计 |
| 元数据 | SQLite | 单机单用户足够；大并发或云部署时需要调整 |
| 长任务 | 独立于页面重跑的单任务执行器 | 页面刷新不能重复提交；不立即引入 Redis/Celery |
| 视频后端 | 独立运行的 MoneyPrinterTurbo API | 避免深入改动上游；需要管理服务启动和双端文件路径 |
| 模型服务 | 一个可访问的云 LLM，选择一种受支持 TTS | 缩小适配面；成本和可达性待实测 |

此为方案建议，未生成框架文件。暂不引入 LangChain/LangGraph；只有固定流程明显无法满足需求时再评估。若教师要求前后端分离，可评估 FastAPI 加 Web 前端，但需同步调整工期。

ContentFlow 负责选题、审核、版本、工作流和记录；上游负责媒体处理和合成。默认不 fork 上游、不重复实现编码器。若验证发现 API 无法保留已审核脚本或使用指定本地素材，应先记录差距，再讨论最小上游扩展，不能静默取消审核要求。

### 10.3 分项评估

| 方面 | 判断 | 下一步证据 |
| --- | --- | --- |
| 选题和脚本 | 可行但输出不稳定 | 实测结构化结果、中文长度及自然语言修改 |
| 素材处理 | 本地素材方案可控 | 实测上传、校验、路径映射与画幅裁切 |
| 视频生成 | 上游具备能力，集成风险中等 | 一条真实样片、接口响应与产物文件 |
| Agent 编排 | 固定流程可实现 | 状态转换、审核约束、失败与重复提交验证 |
| 运行环境 | 当前未知 | 本机 Python、FFmpeg、字体、内存、磁盘、网络检查 |
| 经济性 | 尚不能报价 | 记录 token、TTS 用量及供应商计费；先确定预算 |
| 课程适配 | 方向契合，评分规则待确认 | 教师对开源复用和自然语言开发证据的具体要求 |

### 10.4 联调验证门槛

下一阶段获准开发后，先做最小技术验证：锁定上游 release/commit；核验环境；用指定中文脚本和本地素材提交一次生成；观察状态；取回并播放成片；确认字幕字体与分辨率；验证服务停止及重复提交时的行为。

通过标准：真实 MP4 可播放；审核稿没有被替换；本地素材确实进入输出；记录上游版本、配置摘要和耗时。未通过前，不把大部分时间投入界面美化。无法通过时先分析版本或配置原因；若需更换视频后端，另作需求与工作量评审。

## 11. 风险与资源预算

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游更新和接口变化 | 联调失效 | 锁定版本和依赖，保存接口样例与适配检查记录 |
| 国内网络或凭证限制 | LLM/TTS/素材不可用 | 先测试可达性；准备本地素材；缓存产物明确标识，不冒充实时生成 |
| TTS 或字体不兼容 | 合成失败或中文乱码 | 优先验证短句和中文字体，再生成完整样片 |
| 模型虚构事实 | 内容错误 | 限定低风险演示主题，保留审核；不宣传自动事实核验 |
| 任务重复执行 | 额外费用和混乱产物 | 保存关联任务、点击去重、不确定状态先核对 |
| CPU、磁盘不足 | 超时或文件缺失 | 单任务执行，限制素材数量与体积，检查空间 |
| 源码与素材授权混淆 | 交付使用条件不清 | 分别记录依赖、字体、音乐和素材来源 |
| 功能扩张 | 无法按时完成 | 冻结 P0，P1 只在核心验收后安排 |

成本模型：LLM 输入与输出用量费用 + TTS 用量费用 + 素材服务费用（如有）+ 本地计算及存储成本。付费额度、价格和试用状态待选定服务后核验，不承诺零成本。先用 3 个短任务测量每次尝试用量，再估算“演示次数 × 平均成本 × 重试余量”；无实际用量时只能给预算方法。

## 12. 验收计划与需求追踪

| 场景 | 覆盖需求 | 需要保留的证据 |
| --- | --- | --- |
