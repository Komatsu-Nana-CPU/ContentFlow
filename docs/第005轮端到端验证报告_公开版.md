## 3. Edge 失败、定位、批准与修复

1. 核对本机固定 1.3.6 的 `voice.py`：普通中文音色进入 Azure TTS v1，即 `edge_tts.Communicate` 免费联网路径；该路径不读取额外用户 API Key。字幕使用 WordBoundary 及 SubMaker。它不是离线服务，未来可用性没有保证。
2. 锁定依赖 7.2.7 的原生调用执行其内置 3 次尝试，每次 30 秒，总计约 90.027 秒，未返回音频。尚未创建视频任务。
3. DNS、TCP/TLS 检查通过；对同一安装版本执行一次直接异步诊断，得到 `WSServerHandshakeError`、HTTP 403。通过已有本机代理对照仍为 403。没有修改系统代理或读取代理凭证。
4. 安装包的同步流通过线程和队列取事件，没有传播工作线程异常；上游 30 秒超时保护使这个底层 403 表现为超时。该诊断依据实际本机 `communicate.py`，未修改它。
5. [Edge 官方发行说明](https://github.com/rany2/edge-tts/releases) 记录 7.3.0 新增握手协议支持，7.3.1 修复服务端日期解析；[官方修复 PR](https://github.com/rany2/edge-tts/pull/492) 与 [问题记录](https://github.com/rany2/edge-tts/issues/490) 提供背景。版本/协议差异是本次故障的合理解释；对本机最直接的证据是同文本同音色在批准升级后成功。
6. Codex 提出仅升级独立 `.venv` 的 edge-tts；用户明确回复 **“同意，仅升级独立环境中的 edge-tts”** 后执行。没有更换 MoneyPrinterTurbo 版本、改源码或改 uv.lock。
7. 7.3.1 下原生 TTS 第一次尝试成功，独立音频为 43,056 字节、7.18 秒，17 个词边界，生成三段句级字幕。

本机已安装 Windows zh-CN 离线识别器；对独立音频和成片音轨执行辅助识别，无下载或上传。识别出中文主体内容，但“内容流”“测试视频”等有误识别，置信度约 0.35–0.36。它只作为中文音轨辅助证据，不是精确转写或人工试听结论。一次临时 PowerShell 检查遗漏加载 System.Speech 程序集，补充后运行；同步识别结束时输入耗尽异常已单独记录，不作为媒体解码失败。
